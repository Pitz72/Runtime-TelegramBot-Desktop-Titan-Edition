# Runtime TelegramBot Titan Edition — Changelog v1.7.7

**Data di Rilascio:** 27 Marzo 2026

## 🔒 Security Patch — Criticità Gravissime

Questa release è interamente dedicata alla risoluzione delle tre criticità di sicurezza gravissime identificate nell'analisi tecnica del 27/03/2026.

---

### [C1] Cifratura token nei file `.rtb` (OmniSync)

**Problema risolto:** Il token del bot Telegram veniva esportato in **plaintext** nei file `.rtb`, rendendo possibile l'accesso al bot da parte di chiunque entrasse in possesso del file.

**Soluzione implementata in `src/main/bot/manager.ts`:**
- Aggiunta cifratura **AES-256-CBC** con IV casuale a ogni export.
- Il token viene cifrato prima di essere scritto nel JSON dell'`.rtb` tramite le funzioni `encryptTokenForExport()` e `decryptTokenFromExport()`.
- La chiave è derivata da un segreto interno dell'app tramite SHA-256, garantendo portabilità cross-machine senza richiedere input utente.
- **Backward compatibility:** i file `.rtb` precedenti alla v1.7.7 (con token in plaintext) vengono ancora importati correttamente tramite fallback automatico.

---

### [C2] Validazione anti-SSRF sugli URL dei feed

**Problema risolto:** Gli URL inseriti dall'utente per i feed RSS/Podcast venivano passati direttamente alla funzione di fetch senza alcuna validazione, rendendo possibile richiedere risorse da indirizzi di rete privata (SSRF — Server-Side Request Forgery).

**Soluzione implementata in `src/main/bot/parser.ts` e `src/main/bot/youtube.ts`:**
- Nuova funzione `validateFeedUrl(url)` esportata da `parser.ts`.
- Blocca schemi diversi da `http://` e `https://`.
- Blocca indirizzi loopback (`localhost`, `127.x.x.x`, `::1`), indirizzi privati RFC-1918 (`10.x`, `172.16-31.x`, `192.168.x`), link-local (`169.254.x`), e `0.0.0.0`.
- La validazione è applicata in `fetchFeed()` (parser) e in `fetchYouTubeVideos()` per i casi in cui l'input è un URL completo.
- Gli stessi controlli vengono applicati negli handler IPC `add-feed` e `update-feed`.

---

### [C3] Validazione input sugli handler IPC

**Problema risolto:** Tutti gli handler IPC accettavano i parametri dal renderer senza alcuna validazione di tipo, range o formato, permettendo input malformati o malevoli di raggiungere il database e il motore.

**Soluzione implementata in `src/main/ipc.ts`:**
- Aggiunto blocco di helper di validazione: `assertString()`, `assertPositiveInt()`, `assertCheckInterval()`, `assertTimeOrDefault()`, `assertFeedType()`.
- Validazione applicata agli handler: `create-bot`, `update-bot`, `delete-bot`, `add-feed`, `update-feed`, `delete-feed`, `toggle-feed`, `clear-history`, `get-stats`.
- `check_interval` accetta solo valori interi tra 1 e 1440 (1 minuto — 24 ore).
- `send_from` / `send_until` devono rispettare il formato `HH:MM` (`/^([01]\d|2[0-3]):([0-5]\d)$/`).
- Gli errori di validazione vengono propagati al renderer come eccezioni gestite.

## 🧹 Pulizia Dipendenze

Rimosse dal `package.json` le 4 dipendenze orfane non più importate nel codice sorgente:
- `react-markdown` — aggiunta in v1.7.6 per le guide in-app, rimossa la feature ma non la dipendenza

- `yt-channel-info` — idem
- `ytpl` — idem

## Note per gli sviluppatori

I file `.rtb` generati da v1.7.7 in poi hanno il campo `token` nel seguente formato cifrato:
```json
"token": "{\"e\":\"<ciphertext_base64>\",\"iv\":\"<iv_base64>\"}"
```
I file generati da versioni precedenti (token in plaintext) continuano a essere importati correttamente.
