# Titan Edition v1.7.9

**Data**: 13 Aprile 2026

## 🔧 Bug Fix Critico — YouTube Feed Ripristinato

### Aggiornamento `youtubei.js` da v14.0.0 a v17.0.1
- **Problema**: Tutti i feed YouTube configurati (Radio Anziano, Runtime Radio, Archeologia Informatica, Avvocati e Mac, Ulti.Media, Daniele Borghi, MagnetarMan, Roberto Marin) restituivano **0 items** ad ogni ciclo di check senza generare errori. I video pubblicati (es. Radio Anziano alle 07:00 del 13/04/2026) non venivano rilevati né inviati ai canali Telegram.
- **Causa**: La libreria `youtubei.js` (Innertube) versione 14.x è diventata incompatibile con le API interne di YouTube, aggiornate nel corso del 2026. La funzione `channel.getVideos()` restituiva un array vuoto senza eccezioni, rendendo il problema silenzioso — nessun errore visibile nei log.
- **Soluzione**: Aggiornamento diretto alla versione stabile **17.0.1**, che supporta le nuove API interne di YouTube e i meccanismi di autenticazione/impersonation aggiornati (PO Token, client context).
- **File**: `package.json`

## ⚙️ Miglioramenti al Modulo YouTube (`youtube.ts`)

### Gestione Sessione Innertube con Auto-Reset
- **Prima**: L'istanza `Innertube` veniva creata una sola volta e cachata per tutta la durata dell'applicazione. Sessioni stale potevano causare risposte vuote o rifiuti silenzionsi dal server YouTube.
- **Dopo**: L'istanza viene rigenerata automaticamente ogni **30 minuti** (`SESSION_MAX_AGE_MS`). In caso di risposte vuote (0 video) o errori, la sessione viene resettata immediatamente per forzare una nuova autenticazione al ciclo successivo.
- Aggiunta funzione esportata `resetYouTubeSession()` per reset manuale se necessario.

### Logging Diagnostico Completo
- Tutti i log YouTube ora passano attraverso `TitanLogger` (visibili nel terminale della Dashboard), invece di `console.error` (visibile solo nel DevTools del main process).
- Nuovi messaggi di log aggiunti:
  - `[YouTube] New Innertube instance created` — conferma creazione sessione
  - `[YouTube] Session expired, creating new instance...` — auto-reset per età
  - `[YouTube] Resolving channel: <id>` — inizio risoluzione canale
  - `[YouTube] Channel found: <nome>` — conferma canale trovato
  - `[YouTube] Raw videos count: <N>` — conteggio video grezzi ricevuti dalla API
  - `[YouTube] WARNING: No videos returned...` — allarme risposte vuote con reset automatico
  - `[YouTube] Parsed N valid items from <canale>` — riepilogo finale
  - `[YouTube] Skipping upcoming/premiere: <titolo>` — video filtrati

### Accesso Dati Video Robusto (Compatibilità v17)
- L'accesso ai video dal risultato di `getVideos()` ora usa un fallback chain: `videosTab.videos || videosTab.contents || []` per garantire compatibilità con eventuali cambiamenti nella struttura della risposta.
- L'ID video usa fallback: `v.id || v.video_id`.
- Il titolo usa fallback: `v.title?.text || v.title`.
- La descrizione usa fallback: `v.description_snippet?.text || v.short_description`.
- Il nome del feed usa fallback: `channel.metadata?.title || channel.title`.

### Fallback Thumbnail Multiplo
- **Prima**: Solo `v.thumbnails[0].url` — se la struttura cambiava, l'immagine era `undefined`.
- **Dopo**: Chain di fallback a 4 livelli:
  1. `v.thumbnails[0].url`
  2. `v.best_thumbnail?.url`
  3. `v.thumbnail?.url`
  4. URL statico YouTube: `https://i.ytimg.com/vi/{videoId}/hqdefault.jpg`
