# Titan Edition v1.7.8

## 🔧 Bug Fix Critici

### Fix Escape URL nei Template Telegram
- **Problema**: Le URL contenenti il carattere `&` (comuni in WordPress, podcast e link con tracking) causavano un errore `Bad Request: can't parse entities` da parte di Telegram. Questo innescava un loop di 5 retry per ogni articolo problematico, bloccando la coda di invio per tutti i bot.
- **Soluzione**: Introdotta la funzione `escapeUrl()` che codifica i caratteri `&` negli attributi HTML (`href`), applicata a `{{link}}` e `item.image`. L'escape generico (`escape()`) continua a proteggere titoli, summary e nomi feed.
- **File**: `src/main/bot/telegram.ts`

### Unificazione Canali Log IPC
- **Problema**: Il `TelegramClient` inviava log tecnici (errori di rete, FloodWait, retry) su un canale IPC separato (`bot-log`) che l'interfaccia non ascoltava. L'utente vedeva solo "Send failed" senza dettagli diagnostici.
- **Soluzione**: Il `TelegramClient` ora utilizza `TitanLogger.log()` (canale `bot-logs-batch`), rendendo tutti i log del client Telegram visibili nel terminale della Dashboard in tempo reale. Rimossa la dipendenza diretta da `BrowserWindow`.
- **File**: `src/main/bot/telegram.ts`

## 📦 Ottimizzazione Build — Riduzione Installer del 95%

### Problema
A partire dalla v1.7.7, l'installer Windows era cresciuto da ~94 MB a 327 MB (v1.7.7) e poi a **1.5 GB**. La causa era l'inclusione dell'intero albero `node_modules` (6,317 file) nell'archivio asar, dovuta a due problemi concorrenti:

1. **Vite SSR mode** (`ssr: true` nella config del main process) esternalizzava **tutte** le dipendenze (react, telegraf, youtubei.js, framer-motion, ecc.) invece di bundlarle nel `.cjs`. Il bundle risultante era solo 59 KB — il resto era tutto in node_modules.
2. **Doppia configurazione electron-builder**: I pattern `files` nell'`electron-builder.yml` venivano **ignorati** perché il campo `"build"` nel `package.json` (che ha precedenza) non li definiva, risultando in un `files: []` (= includi tutto) nella config effettiva.

### Soluzione
- **`vite.config.ts`**: Aggiunto `ssr: { noExternal: true }` alla sezione main build, forzando Vite a bundlare **tutte** le dipendenze JS inline nel `.cjs` finale, tranne `better-sqlite3` (modulo nativo) ed `electron`. Il bundle del main process è passato da 59 KB a ~3.1 MB (1,142 moduli trasformati).
- **`package.json` (build field)**: Aggiunti pattern `files` espliciti che escludono `node_modules` e re-includono solo la catena nativa: `better-sqlite3` → `bindings` → `file-uri-to-path`. Aggiunto `asarUnpack` per i file `.node` nativi.
- **`electron-builder.yml`**: Allineato con la stessa configurazione per coerenza.

### Risultati

| Metrica | v1.7.7 (Pre-fix) | v1.7.8 (Post-fix) | Riduzione |
|---|---|---|---|
| Installer `.exe` | 1,505 MB | **80.9 MB** | **-95%** |
| Archivio `.asar` | 1,502 MB | **17 MB** | **-99%** |
| File nell'asar | 6,317 | **66** | **-99%** |

### File Modificati
- `vite.config.ts` — `ssr.noExternal: true`
- `package.json` — sezione `build.files` e `build.asarUnpack`
- `electron-builder.yml` — pattern `files` e `asarUnpack` allineati
