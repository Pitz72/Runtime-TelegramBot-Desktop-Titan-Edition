# v1.1.0 — Major Feature Release (2026-02-24)

## 🆕 Nuove Funzionalità

### ⚙️ Intervallo di Polling Configurabile
- **Slider nelle Impostazioni Bot:** Aggiunto controllo a slider (range: 1–120 minuti) nelle impostazioni di ciascun bot per definire ogni quanto l'engine controlla i feed RSS.
- **Default 15 minuti:** Il valore predefinito resta invariato per compatibilità con le versioni precedenti.
- **Migrazione Automatica:** Al primo avvio, il database viene aggiornato automaticamente con la nuova colonna `check_interval`. I bot esistenti mantengono il valore di default.
- **Polling Dinamico:** L'engine utilizza `setTimeout` (anziché `setInterval`) e calcola dinamicamente l'intervallo di attesa basandosi sul minimo tra tutti i bot attivi.

### ✅ Pulsante Test Feed
- **Verifica istantanea:** Nuovo pulsante "Test" con icona ⚡ accanto al campo URL nel Feed Manager. Permette di verificare la validità di un URL RSS prima di salvarlo.
- **Feedback visivo:** Mostra risultato colorato (✅ verde = feed valido con conteggio elementi, ❌ rosso = errore con messaggio). L'indicatore ha un'animazione di caricamento (spinner) durante il test.
- **Backend IPC handler:** Nuovo endpoint `test-feed` che esegue il parser RSS direttamente sull'URL fornito, senza salvare nulla nel database.

### 📊 Statistiche Invio
- **Pannello Stats nella Dashboard:** Tre contatori visivi (Oggi / 7 Giorni / Totale) posizionati simmetricamente ai lati del pulsante Ignition.
- **Query SQL ottimizzate:** Nuova funzione `BotManager.getStats()` che calcola i conteggi dal campo `sent_at` della tabella `history`.
- **Aggiornamento periodico:** Le statistiche si aggiornano automaticamente ogni 30 secondi quando l'engine è in esecuzione, e al cambio di bot selezionato.

### 📋 Export Log
- **Pulsante "Export" nel pannello log:** Nuovo pulsante con icona Download nella barra del pannello log.
- **Dialog di salvataggio nativo:** Utilizza `dialog.showSaveDialog()` di Electron per scegliere il percorso di salvataggio. Nome file predefinito: `titan-log-YYYY-MM-DD.txt`.
- **Formato output:** I log vengono salvati in formato testo puro (.txt), uno per riga, con i timestamp originali.

### 🚫 Notifiche Desktop (ANNOTATO)
- Feature pianificata ma **rimandata a versione futura**. Utilizzerà l'API `Notification` di Electron per notifiche di sistema al completamento degli invii.

## 🔧 Qualità del Codice

### 🛡️ Eliminazione @ts-ignore
- **Creato `env.d.ts`:** Nuovo file di dichiarazione dei tipi per `Window.api` con interfaccia `TitanAPI` completa. Fornisce type-checking completo su tutte le chiamate IPC dal renderer.
- **Rimossi 14 `// @ts-ignore`:** Ogni componente React ora usa tipi espliciti per le chiamate API, eliminando completamente il rischio di errori silenziosi sui nomi/parametri delle funzioni IPC.
- **Componenti aggiornati:** `App.tsx`, `Dashboard.tsx`, `FeedManager.tsx`, `BotSelector.tsx`, `BotSettingsModal.tsx` — tutti senza `@ts-ignore`.

### 🔄 Fix Tipo `RssItem` Duplicato
- **Problema:** L'interfaccia `RssItem` era definita identicamente sia in `shared/types.ts` che in `bot/types.ts`, con rischio di drift silenzioso.
- **Soluzione:** `bot/types.ts` ora esporta solo un re-export: `export type { BotConfig, FeedConfig, RssItem } from '../../shared/types'`. La definizione canonica è in un unico posto.

### 🛑 Fix Parametro `botId` Morto nel Preload
- **Problema:** `preload/index.ts` esponeva `startBot: (botId: number) => ...` ma l'IPC handler ignorava completamente il parametro e avviava comunque tutti i bot.
- **Soluzione:** Rimosso il parametro `botId` dalla firma di `startBot`. Ora è `startBot: () => Promise<{success, error?}>`.

### 🔁 Fix Query Ridondante in `processFeed`
- **Problema:** `processFeed` in `engine.ts` rieseguiva `BotManager.getBots().find(b => b.id === botId)` ad ogni feed processato, sebbene il bot fosse già disponibile nel caller.
- **Soluzione:** `processFeed` ora riceve direttamente l'oggetto `bot: BotConfig` dal loop padre, eliminando N query ridondanti per ciclo.

### 🗑️ Sincronizzazione `deleteBot` con Engine
- **Problema:** Eliminare un bot dal database non notificava l'engine runtime. Il `TelegramClient` associato restava nella `Map<number, TelegramClient>` dell'engine.
- **Soluzione:** `ipc.ts` ora chiama `botEngine.removeClient(id)` prima di `BotManager.deleteBot(id)`. Il metodo `removeClient()` esegue l'abort del client e lo rimuove dalla mappa.

### 📝 `.gitignore` Aggiornato
- Aggiunte regole mancanti: `.env`, `.DS_Store`, `Thumbs.db`, `*.tsbuildinfo`, `build_log*.txt`.

### 📄 Preload Bridge Tipizzato
- Riscrittura completa di `preload/index.ts` con parametri tipizzati per ogni funzione. Aggiunta di `testFeed`, `getStats`, `exportLogs` come nuovi endpoint esposti.

## 🗄️ Database

### Migrazione v1.1.0
- **Nuova colonna `check_interval`:** Aggiunta alla tabella `bots` con tipo `INTEGER DEFAULT 15`.
- **Retrocompatibilità:** La migrazione controlla l'esistenza della colonna prima di aggiungerla. I bot esistenti ricevono il valore di default (15 minuti).
- **Nessuna azione richiesta:** L'aggiornamento è completamente automatico al primo avvio della v1.1.0.

### Schema attuale

```sql
CREATE TABLE bots (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    token TEXT NOT NULL,
    channel_id TEXT NOT NULL,
    start_date DATETIME DEFAULT CURRENT_TIMESTAMP,
    check_interval INTEGER DEFAULT 15,  -- NEW in v1.1.0
    is_active BOOLEAN DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

# v1.1.9 (2026-02-17)

### 🚨 Critical Fixes
- **Channel ID**: Il bot ora normalizza automaticamente il Channel ID da qualsiasi formato (`https://t.me/NomeCanale`, `t.me/NomeCanale`, `NomeCanale`) a `@NomeCanale`. Questo risolveva l'errore "Bad Request: chat not found".
- **Stop Immediato**: Premere Stop ora interrompe immediatamente qualsiasi invio in corso. Il retry loop viene abortito istantaneamente invece di continuare i tentativi.

### 🐛 Bug Fixes
- **Errori Fatali**: Gli errori fatali di Telegram (chat not found, bot blocked, unauthorized) non vengono più riprovati inutilmente. Il bot si ferma subito e logga l'errore.
- **Sleep Interrompibile**: Tutte le attese del retry loop (FloodWait, errori di rete) vengono controllate ogni 500ms per abort, garantendo uno stop reattivo.
