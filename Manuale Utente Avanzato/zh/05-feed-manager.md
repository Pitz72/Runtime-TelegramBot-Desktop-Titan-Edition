## 第 5 章：Feed Manager（来源）

### 5.1 添加并测试来源
Feed Manager（机器人列表下方的面板）是您机器人的"食谱"：您在这里输入 Titan 将去抓取内容的网址（URL）。

要添加一个来源：

1. 选择您想为其分配来源的机器人。
2. 点击 **添加来源**。
3. 给来源起一个**名称**。这不是随便的标签：它是您可以印在消息顶部、作为新闻署名的文字（即模板中的 `{{feedName}}` 字段，第 6 章）。
4. 选择**类型**：
    -   **播客：** 用于音频流（MP3）。Titan 会尝试获取封面图，它常常藏在 Spreaker 或 AzuraCast 等服务使用的 *iTunes* 标签里。
    -   **新闻：** 用于博客、资讯网站或报纸的常规文章。
5. 粘贴该源的 URL（通常是以 `.xml` 或 `.rss` 结尾的地址）。

保存之前，您可以使用 **测试（⚡）** 按钮：它会对链接发起一次真实调用，并立即告诉您它是否响应。如果源有效，一条绿色提示会报告找到了多少条新闻；如果有问题（网站离线、链接错误），提示则为红色。测试只是一次检查：它不强制您做任何事，您仍可照常保存，但这是避免输入错误地址的最快方式。

![添加新来源的表单，含名称、类型、URL 和测试按钮。](screenshots/06-feed-form.png)

列表中的每个来源都有一个开关，用于启用它或将其暂停而不删除，还有用于修改或删除它的图标。

![来源列表：类型、活跃过滤器的徽章，以及每个源的开关。](screenshots/13-feed-list.png)

如果某个来源不再响应（例如出现 404 错误），您会注意到：系统日志中会出现一行红色、带有该源名称的记录。而如果您在想能添加多少个来源，并没有硬性上限：不过请记住，引擎是轮流检查它们的，因此当有几十个源（或很多机器人）时，一整轮检查会变长。

### 5.2 原生的 YouTube 支持
通常，把 YouTube 接入自动化系统是件麻烦事：它需要 Google Cloud 上的开发者账号和一个 API 密钥，还有相应的费用和限额。Titan 借助 *InnerTube* 省去了这一切——这是一个像浏览器那样读取 YouTube 页面的引擎，完全不需要密钥。

1.  在 **添加来源** 中选择类型 **YouTube（视频）**。
2.  在 URL 字段中，既不需要奇怪的代码，也不需要 XML 源：粘贴频道的 handle（YouTuber 名字下方的 @，例如 `@RuntimeRadio`），或从浏览器复制的完整频道地址。

其余的交给 Titan。不过有一个有用的防范措施：**防首映过滤器**。当某位 YouTuber 安排了直播或一段"两天后上线"的视频时，YouTube 仍会把它显示在列表顶部。天真的机器人会立刻发出通知，而点击的人会进入一段尚不可用的视频。Titan 则会检查视频的状态：如果它被标记为 *upcoming* 或 *premiere*，它会把它丢弃，只在它真正可见时才发布。

### 5.3 源的高级选项
当您添加或修改一个来源时，在主要字段的下方有三项可选设置。您可以忽略它们（源用默认值也能很好地工作），也可以用它们来做更精细的控制。

-   **关键词过滤。** 两个字段，"包含"和"排除"，词与词之间用逗号分隔。如果填写"包含"，Titan 只发布标题或正文中至少出现其中一个词的内容；如果填写"排除"，则丢弃含有其中任何一个词的内容。来源上的琥珀色徽章表示过滤器已启用。
-   **自定义间隔。** 通常，每个源都遵循机器人的检查节奏。在这里，您可以给它一个专属的节奏，从 5 分钟到 24 小时：便于更频繁地检查一个非常活跃的网站，或更少地检查一个缓慢的网站。徽章会显示所设的间隔。
-   **摘要。** Titan 可以不在每条内容一出现就发布，而是把它们累积起来，按固定周期（1 小时、6 小时、12 小时、24 小时或 7 天）合并到一条汇总消息里发送。汇总会列出各标题并附"阅读"链接，每条消息最多 20 条内容。这对内容繁多的来源很有用，否则它们会淹没频道。紫色徽章表示摘要已启用。

### 5.4 一次导入多个源（OPML）
如果您已经在某个 RSS 阅读器里有一份源列表，就不必再手动重新输入。Feed Manager 顶部的 **OPML** 按钮会一次性批量导入一个标准 `.opml` 文件中包含的所有来源——这是 RSS 阅读器导出其列表所用的格式。完成后，Titan 会告诉您添加了多少个源。
